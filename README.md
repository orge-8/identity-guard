# 群聊身份识别（identity-guard）

> MaiBot 第三方插件 · 防「改群名片冒充他人」

## 它解决什么问题

群名片是**随便改的**，QQ 号是**改不了的**。常见骗术：把群名片改成群主/管理员/熟人，
然后在群里要钱、要密码、发假链接。群成员只看名字很容易中招。

本插件把身份锚定在 QQ 号上：长期记录「谁在什么时候用过什么名片」，
一旦有人改名（或新人进群）后与**其他账号**正在使用或曾使用过的名片相同或高度相似，
立刻在群里发身份提醒，并随时可查档案、追溯改名时间线。

## 工作原理

```
入站群消息 ──> 取 (群号, QQ号, 当前群名片)
                  │
                  ├─> 建档：首次见到 → 记录「该 QQ 号的首个名片 + 时间」
                  ├─> 改名：名片变了 → 写改名事件，旧名片进历史
                  └─> 撞名：新名字 vs 群内**其他账号**的当前/历史名片
                          ├─ 归一化（去空格 / 去 emoji / 去符号 / 英文小写）后比较
                          ├─ 完全一致 或 相似度 ≥ 阈值 → 判定疑似冒充
                          └─ 冷却内不重复刷 → 群内发提醒
```

归一化能挡住这类伪装：`张三` / `张 三` / `张三✨` / `Zhang-San` 会被判为同一个名字。

**误报控制**：同一个 QQ 号换回自己曾用过的名字不算冒充；可信名单内成员本人改名不提醒；
长度过短（默认 < 2 字）的名字不参与比对；提醒有单人 + 群级双重冷却。

## 命令

| 命令 | 谁可用 | 说明 |
|---|---|---|
| `/身份 <QQ号\|名字\|@某人>` | 所有人 | 查某人档案：当前名片、首次/最近发言、历史名片（含起用时间与发言次数）、可信状态、备注 |
| `/身份` | 所有人 | 不带参数 = 查自己 |
| `/我是谁` | 所有人 | 查自己的档案（别名 `/我的身份`） |
| `/改名记录 [条数]` | 所有人 | 本群最近的群名片变更时间线（默认 10 条，别名 `/身份记录`） |
| `/身份信任 <QQ号> [群号]` | 管理员 | 加入可信名单（别名 `/身份取消信任 <QQ号>` 移出）；本地控制台执行时必须带群号 |
| `/身份备注 <QQ号> <备注>` | 管理员 | 写身份备注（如「群主，已线下核实」）；备注留空即清除 |
| `/身份状态` | 管理员 | 群数 / 档案数 / 事件数 / 阈值 / 开关状态（别名 `/身份统计`） |

管理员由 `guard.admin_ids` 配置；本地控制台（bot_console）天然放行。

## LLM 工具

| 工具 | 用途 |
|---|---|
| `check_identity` | 核验某人身份（按 QQ 号或名字），返回名片历史。适合「我是群主」「给我转 500」这类需要证实的场景 |
| `recent_name_changes` | 查看本群最近的改名记录，排查「这到底是谁改的」 |

Bot 可以直接在对话里调用，例如用户问「刚说话的这个真是小明吗」，它会调 `check_identity`
拿到「QQ 10002，8 月 20 日起叫『小明』，之前叫『隔壁老王』，改名 3 次」再作答。

## 安装与启用

1. 把整个 `identity-guard` 目录复制到 MaiBot 的 `plugins/` 下
2. **完整重启 MaiBot**（manifest 里的 capabilities 在加载前校验，热重载不生效）
3. 在 WebUI 插件页启用，填 `guard.admin_ids`（否则管理命令没人能用）
4. 验证：`/身份状态` 有输出即插件在线；群内说几句话后再 `/身份` 应能看到自己的档案

> 改 `capabilities` 必须重启；只改 `config.toml` 可热重载。

## 配置

见 `config.example.toml`（真实生效的是自动生成的 `config.toml`，不入库）。关键项：

| 配置 | 默认 | 说明 |
|---|---|---|
| `guard.similarity_threshold` | `0.86` | 相似度阈值，调低更灵敏也更容易误报 |
| `guard.min_name_length` | `2` | 短于此长度的名字不参与比对 |
| `guard.alert_enabled` | `true` | 是否在群里发提醒（关掉后仍静默建档，可随时手动查） |
| `guard.alert_cooldown_seconds` | `600` | 同一人同一名字的提醒冷却 |
| `guard.group_alert_cooldown_seconds` | `60` | 同群两次提醒的最小间隔 |
| `guard.trusted_user_ids` | `[]` | 可信名单（本人改名不提醒，被冒用照常提醒） |
| `guard.admin_ids` | `[]` | 管理命令白名单 |
| `guard.ignored_user_ids` | `[]` | 完全跳过（机器人小号等） |

## 数据存储

- 位置：`<MaiBot根>/data/plugins/org.mai-mai.identity-guard/identity_store.json`（经 `ctx.paths.data_dir`）
- 结构：按群 → 按 QQ 号存名片历史 + 改名事件；原子写盘，损坏时自动备份为 `.corrupt` 并重建
- 上限：每人 20 个历史名片、每群 300 条改名事件、每群 2000 份档案（可在配置里调）

## 能力边界（重要）

- **只认 QQ 号，不认头像/签名**：QQ 号改不了，这是插件可信的根基
- **只记录插件上线之后的数据**：装之前的历史查不到，档案会随发言逐步积累
- **依赖适配器提供展示名**：napcat-adapter 提供群名片时识别的是群名片；只提供昵称时识别的是昵称。
  如果适配器两者都不给，插件无法建档（`/身份状态` 的成员数会一直是 0）
- **判定是"疑似"而非"实锤"**：同名的好人、情侣互改名都会触发，所以文案是提醒不是指控，
  严重误报把人加进 `trusted_user_ids` 即可

## 安全与防护说明（v1.0.1 上线前全检沉淀）

- **无凭据外发 / 无 SSRF 面**：插件不发任何外部 HTTP 请求，唯一外部调用是
  napcat 适配器的 `get_login_info`（本机 RPC），无用户可控 URL
- **无 eval / 反序列化风险**：档案持久化只走 `json.loads` / `json.dumps`
- **路径安全**：唯一写盘位置是 `ctx.paths.data_dir` 下固定文件名 `identity_store.json`，
  原子写（tmp + `os.replace`），损坏自动备份为 `.corrupt` 并重建；不处理用户输入的文件名
- **防检测绕过（v1.0.1）**：纯 emoji/纯符号名字（归一化为空）不参与记账，
  堵住「用 emoji 中间态改名再改成受害者名字」的盲区（`test_audit.py` F1 证据）
- **防 Tool 参数撞名（v1.0.1）**：`check_identity` 的 LLM 参数改名 `target_user_id`，
  避免与 Host 注入的调用者 `user_id` 上下文同名歧义（`test_audit.py` F2 证据）
- **防内存无界增长（v1.0.1）**：群级冷却字典过期条目随 `_prune_cooldown` 一并清理
  （`test_audit.py` F3 证据）
- **鉴权边界**：`/身份信任`、`/身份备注`、`/身份状态` 走 `admin_ids` 白名单，
  本地控制台（`is_local_operator`）放行属于 Host 语义——控制台在宿主机上，等同管理员
- **注入面小**：提醒模板字段全部来自内部档案（QQ 号/名片/时间），模板渲染失败自动回退
  默认文案；`alert_template_*` 是配置项，仅管理员可经 WebUI 修改
- **日志不泄密**：日志只含 QQ 号、名片、时间戳，无凭据类数据
